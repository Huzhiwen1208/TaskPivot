# 拾光使用与开发指南

## 1. 第一次运行

在 macOS「终端」检查运行环境：

```bash
node --version
npm --version
cd /Users/jackhu/src_code/task-pivot/ai-frontend
npm install
npm run dev
```

使用 Node.js 20.19+ 或 22.12+。开发服务器地址会显示在终端，默认 `http://127.0.0.1:5173/`；若被占用，请打开 Vite 实际显示的地址。按 `Control C` 停止开发服务器。

代码保存在上述项目目录，修改页面、样式和数据后，开发服务器会自动热更新。`package.json` 定义运行命令，`package-lock.json` 固定依赖版本，`tsconfig.json` 启用严格类型检查，`vite.config.ts` 配置构建与代码拆分。

`.env.example` 保留公开环境变量的示例；当前站点信息统一在 `src/data/site.ts` 维护。Vite 中以 `VITE_` 开头的变量会进入浏览器代码，服务端密钥应由未来接入的后端保存。

## 2. 页面与导航

项目使用 `HashRouter`。下面的路径写在 `#` 后：

| 页面 | 路径 | 常见操作 |
| --- | --- | --- |
| 首页 | `/#/` | 阅读最近文章、查看随记、进入其他页面 |
| 全部文章 | `/#/articles` | 搜索、筛选分类和标签、切换分页 |
| 文章详情 | `/#/article/a-digital-garden` | 阅读、查看目录、复制代码、发表评论 |
| 分类标签 | `/#/topics` | 查看不同主题下的文章数量 |
| 分类管理 | `/#/manage` | 整理分类标签和文章归属 |
| 关于 | `/#/about` | 展示个人介绍和学习方向 |
| 联系 | `/#/contact` | 复制邮箱或打开邮件应用 |

顶部标记回到首页，页脚「拾光」进入联系页。页脚「分类管理」进入整理界面。手机屏幕上通过菜单按钮展开导航；任意页面都可以切换主题或打开搜索。

## 3. 添加和修改文章

文章保存在 `src/data/articles.ts` 的 `articles` 数组中，使用 `Article` 类型。复制一篇已有文章，再修改内容：

```ts
{
  id: 'my-first-project',
  title: '我的第一个小项目',
  excerpt: '这篇文章的简短介绍，会显示在文章卡片中。',
  date: '2026-11-14',
  categoryId: 'tech',
  tagIds: ['react', 'project'],
  readTime: 5,
  cover: 'code',
  featured: false,
  markdown: '## 从一个问题开始\n\n这里是 Markdown 正文。',
}
```

字段说明：

- `id`：唯一且尽量稳定的英文标识，用于链接与本地评论关联。修改标题时通常保持它不变。
- `date`：`YYYY-MM-DD` 格式，文章按日期从新到旧展示。
- `categoryId`：引用初始分类的 id；每篇文章属于一个分类。
- `tagIds`：引用标签 id 的数组，可以为空或包含多个标签。
- `readTime`：估算阅读分钟数，由作者填写。
- `cover`：`garden`、`code`、`mountain`、`notes`、`desk`、`light` 之一，对应本地插画。
- `featured`：可选字段，用于精选标识。
- `markdown`：完整 Markdown 字符串。

修改后执行类型检查，并打开对应详情链接。若已在管理页修改过同一文章的归属，浏览器保存的归属会优先于源码初始值；需要验证新的初始分类时，请使用一个没有保存过本地修改的浏览器环境。

### Markdown 写法

支持标题、段落、加粗、斜体、链接、引用、有序/无序列表、表格、任务列表和代码块。以下内容可放进 Markdown 正文：

````markdown
## 我遇到的问题

这是一段正文，**这部分需要强调**。

> 先完成，再一点一点改进。

- [x] 完成页面
- [ ] 补充复盘

| 任务 | 状态 |
| --- | --- |
| 文章列表 | 已完成 |

```typescript
const greeting: string = 'Hello, blog!';
console.log(greeting);
```
````

如果在 TypeScript 的模板字符串中书写 Markdown，正文中的每个反引号前都需要加一个反斜杠；代码围栏中的三个反引号也需要分别转义。可直接参考 `articles.ts` 中的已转义示例。若使用普通引号字符串，则用 `\n` 表示换行。

代码块请标注语言。当前明确注册了 JavaScript、TypeScript、CSS、Bash、JSON、Python 和 XML 语言；纯文本可用 `text`。Markdown 里的原始 HTML 不会执行或渲染为任意 DOM，外部 HTTP(S) 链接会在新标签打开。

文章的二级、三级标题会生成目录。为获得清晰的目录定位，建议同一篇文章中使用不同的标题文字。代码块、表格在窄屏中局部滚动；不要用很长的表格代替普通段落。

## 4. 分类与标签管理

### 修改所有访客的默认内容

编辑 `src/data/articles.ts` 中的 `initialCategories`、`initialTags` 和每篇文章的 `categoryId` / `tagIds`，重新构建并部署。分类、标签都由稳定的 `id` 和显示名称 `name` 组成。

### 在浏览器中整理

打开 `/#/manage`：

1. 在分类或标签输入框填写名称，点击添加。
2. 点击条目旁的编辑图标，修改名称后保存。
3. 删除条目时，先查看确认提示，再决定是否删除。
4. 在“整理文章归属”中选择文章、分类和标签，再点击“保存文章归类”。

名称长度为 1–20 个字符，同一组内不允许重名。至少保留一个分类；删除分类后，关联文章会移入保留分类，优先使用 id 为 `tech` 的分类，否则使用剩余第一个分类。删除标签只移除关联标签，不删除文章。管理页不负责新建或编辑 Markdown 正文。

管理结果仅保存在**当前浏览器、当前站点来源**，不会写回源码，也不会同步给其他访客。它适合前端基础框架、本地整理和交互演示；部署到公开网站后，每位访客看到的初始内容仍由构建时的源码决定。

## 5. 搜索、筛选与分页

可在文章列表输入关键词，也可用 `⌘ K`（macOS）或 `Ctrl K` 打开全站搜索。`Esc` 关闭搜索，回到原入口；按回车打开完整结果列表。

搜索覆盖标题、摘要、正文、标签及分类显示名，不区分英文大小写。空白分隔的多个词按 AND 组合，例如 `React TypeScript` 只显示同时命中两个词的文章。

分类、标签和关键词可以同时生效。筛选后每页展示 6 篇；切换关键词、分类或标签会回到第一页。上一页、下一页和页码按钮反映当前结果；超出范围的页码会使用有效页码，没有结果时提供清除入口。

筛选状态保存在 URL 查询参数中，例如：

```text
/#/articles?q=React&category=tech&tag=project&page=1
```

可以复制链接保存当前筛选。标签和分类参数使用 id，名称调整不会改变对应 id；删除条目后，旧链接可能没有结果，清除筛选即可继续浏览。

## 6. 主题、关于和联系

首次打开页面时，主题跟随系统浅色/深色设置。手动点击主题按钮后，偏好保存在 `localStorage`，后续刷新继续使用该偏好。浅色主题以蓝色为主，深色主题同步调整正文、代码块、表单和插画配色。

在 `src/data/site.ts` 修改站点名称、作者、专业、所在地、介绍、邮箱和 `notes` 随记。当前姓名、专业、城市与文章经历是可替换示例；邮箱 `jackhu.521.rose@gmail.com` 由站点所有者提供。

联系页的“给我写封邮件”通过 `mailto:` 打开用户的邮件应用，不会从网页直接发送邮件。复制按钮需要浏览器提供 Clipboard API；若复制失败，页面提示手动选中邮箱复制。

## 7. 评论基础框架

每篇文章下方有独立评论区。昵称填写 1–24 个字符，评论填写 1–1000 个字符；去除首尾空白后再校验。提交成功后显示在当前文章下方，刷新仍可读取；本地评论支持删除确认。

当前实现没有服务端数据库、登录身份、评论审核和跨访客同步。评论只保存在发布者正在使用的浏览器中，其他设备、其他浏览器或其他访客不会看到这些评论。删除权限也是本地界面行为，不能作为真实用户权限验证。

遇到浏览器存储受限、空间不足或数据格式错误时，会显示明确提示；保存失败不会宣称发布成功。评论以 React 文本节点呈现，输入的 HTML 不会作为可执行 HTML 插入页面。

### 本地保存的数据

| 存储键 | 内容 | 清除后的结果 |
| --- | --- | --- |
| `shiguang-theme` | 手动选择的主题 | 重新跟随系统设置 |
| `shiguang-taxonomy-v1` | 本地分类、标签和文章归属 | 回到源码内的初始分类标签 |
| `shiguang-comments-v1` | 所有文章的本地评论 | 本地评论不再可用 |

`localStorage` 按来源隔离：`localhost` 与 `127.0.0.1`、不同端口、预览站点与正式域名之间的记录不会自动共享。清除站点数据、某些隐私窗口关闭或更换设备，都可能让本地记录不可用。现有界面没有云端备份，请不要把本地评论和管理修改当作唯一的数据存档。

## 8. 测试、生产预览与部署

每次修改后，按顺序执行：

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

- `typecheck` 检查 TypeScript 类型与未使用代码。
- `test` 覆盖搜索组合、分页边界、示例数据、分类重命名与删除后的归属、评论校验及存储异常。
- `build` 生成 `dist/`，并执行类型检查。
- `preview` 检查构建结果；它用于本地预览，不是生产服务器。

建议手动检查桌面、平板和手机宽度：导航是否可操作，文章是否溢出，代码与表格是否局部滚动，搜索是否能用键盘关闭，深浅主题是否易读，分页和评论刷新后是否符合预期。再分别打开正常文章链接、缺失文章链接和首页，确认路径行为。

部署时上传完整 `dist/`。HashRouter 的 `#` 后路由由浏览器处理，静态服务只需返回站点入口，不需要为每篇文章单独生成 HTML 或配置 history rewrite。直接刷新 `/#/article/...` 仍会加载入口页面。

若站点部署到 `/blog/` 等子目录，在 `vite.config.ts` 设置 `base: '/blog/'` 后重新构建，使用 `/blog/#/...` 访问。开发服务器默认监听本机；需要通过局域网测试时，可显式运行 `npm run dev -- --host 0.0.0.0` 并使用 Mac 的局域网地址。

## 9. 结构与性能

- `pages/` 负责页面，`components/` 负责可复用界面，`hooks/` 负责共享状态，`lib/` 保留可独立测试的查询和存储逻辑。
- 文章正文与站点内容保存在 `data/`，避免在页面组件中重复编写内容。
- 阅读、关于、联系、分类和管理页面通过 `React.lazy` 延迟加载。
- Markdown 和代码高亮在阅读页面使用，构建时拆分为独立代码块；高亮只注册需要的语言。
- 插画使用随项目提供的 SVG，正文使用系统中文字体；Markdown 图片设置延迟加载。
- 长代码和表格局部滚动，避免为手机用户制造整页横向滚动。
- 主题初始设置在入口中读取，尽量减少页面打开时主题闪烁。

## 10. 后续接入后端

前端已经把数据和界面分离，可逐步替换数据来源：

1. **文章服务**：将 `data/articles.ts` 的静态数据改为 API 查询结果，保留 `Article` 字段或在适配层转换。文章列表可进一步改为服务端搜索和分页。
2. **分类管理**：在 `useTaxonomy.tsx` 的加载和 `commit` 附近接入分类 API，`lib/taxonomy.ts` 保留名称、引用和归属验证。
3. **评论服务**：将 `lib/comments.ts` 的读取/保存调用替换成异步服务端接口，评论组件增加请求状态、失败重试与取消处理。
4. **身份与权限**：真实后台由服务端验证登录、授权和所有权；前端菜单是否显示不能代替权限校验。
5. **公开评论**：在服务端补充内容长度校验、速率限制和审核策略，再提供跨设备共享。

当前代码不会自动创建账户、发送邮件或把浏览器内的评论上传到外部服务。可以先完成前端课程设计，再根据实际需要迭代到完整服务端系统。
